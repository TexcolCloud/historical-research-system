# Web Workbench

React 工作台提供书架上传、处理进展、人工核对、全文阅读、目录、本书原文检索、自动史料卡、实体及证据关系和 Markdown 导出。网页与独立 MCP 使用同一处理契约；原文入库并完成索引后自动进入独立制卡队列。旧 `kind=cards` 卡片及旧研究记录保留读取和导出。

界面面向单人桌面使用，最低布局宽度为 1080px；`/#/` 进入“继续工作”，优先呈现待核对、后台处理中、上次工作和最近专题。全局侧栏提供继续工作、史料集、全文检索、研究专题和待办五个入口，设置与更新日志置于底部；待处理书籍数和研究待办项数分别显示，研究数量尚未读取时明确提示。专题内保留当前专题及材料、研究记录、关系画布、时间线索、AI 分析五项局部导航。`/#/library` 保留书籍与自动卡片入口，书籍深链及 `/platform.html` 继续可用。单书史料卡入口为 `/#/books/:bookId?tab=research`；`/#/research` 提供人物、机构、地点、文献和事件的实体库，`card`、`entity` 参数保留详情深链，`researchRun` 定位具体任务。`/#/research?view=questions` 只读展示旧问题、选材与笔记并提供导出。各页面切换不会销毁上传会话；阅读、核对和画布默认收起全局侧栏，保留显式展开入口。旧专题工作台深链 `/#/workspace?topic=:topicId` 仍可进入对应画布，不指定专题时进入选题页。

## 启动与开发

完整平台由仓库根目录的统一入口启动，构建后的页面、API 和上传代理共用 `http://127.0.0.1:18170`。前端开发需要 Node.js 24+ 和已启动的平台 API、上传服务。以下 PowerShell 命令均从仓库根目录执行：

```powershell
npm --prefix web ci
npm --prefix web run dev
```

Vite 使用 `http://127.0.0.1:18156`，端口占用时直接报错。指定其他端口可执行 `npm --prefix web run dev -- --port 18157`。

[vite.config.ts](vite.config.ts) 从仓库根目录读取开发配置，代理 API 与上传：

| 浏览器路径  | 默认目标                 | 可选覆盖                  |
| ----------- | ------------------------ | ------------------------- |
| `/api/v2`   | `http://127.0.0.1:18170` | `WORKBENCH_API_ORIGIN`    |
| `/uploads/` | `http://127.0.0.1:18171` | `WORKBENCH_UPLOAD_ORIGIN` |

需要由平台同源代理处理上传时，将上传目标设为 `http://127.0.0.1:18170`。Vite 不启动后端或文档处理。两个 HTML 入口使用同一 React 应用，保留已有页面书签。

## API 契约

[api.ts](src/client/api.ts) 使用 `openapi-fetch`，研究接口的 [api.ts](src/features/research/api.ts) 与专题接口的 [api.ts](src/features/studies/api.ts) 使用同源 `fetch` 并传递取消信号；接口类型均来自生成的 [schema.d.ts](src/client/schema.d.ts)。后端接口变更时，从根目录生成契约：

```powershell
npm --prefix web/tooling/openapi ci
npm --prefix web run contracts
```

[export-contracts.ts](scripts/export-contracts.ts) 调用统一命令 `uv run --no-sync --locked python -m hrs contracts`，导出 `web/openapi.json`，再生成客户端类型。执行前需按根 README 准备根 Python 环境；导出不启动 API、模型或文档处理任务。

契约工具独立锁定 TypeScript 5 的生成器依赖，应用使用 TypeScript 7。接口变更同时提交 OpenAPI 与客户端类型，不手工修改生成文件。

React Router 管理路由，TanStack Query 管理服务端状态；Uppy/tus 提供可恢复上传，Tiptap 编辑 Markdown。`features/studies/` 拥有专题、选材、论据、个人线索、分析及独立 React Flow 画布；`TopicNavigation` 统一专题范围和局部导航，保留各视图的筛选与选择；`canvas-model` 管理持久文档与坐标，抽屉、工具栏、节点和详情分别维护。画布沿用 MIT 许可的 React Flow，无需购买生产许可；[许可声明](public/assets/canvas/README.md) 随构建复制到 `/assets/canvas/README.md`。只读实体关系与个人手工画布各自保留含义。正文、原图、卡片、实体与执行详情按需加载；清单分页读取，画布按引用批量读取上下文，避免首屏分页隐藏已放置记录。

样式按职责组织：`theme.css` 提供语义令牌和本地字体，`workbench.css` 拥有书籍与进展，`study-shell.css` 拥有桌面导航外壳，`review-evidence.css` 拥有正文核对，`reader-navigation.css` 拥有目录、阅读和检索，`research.css` 拥有史料卡、实体与历史记录，`research-reading.css` 拥有卡片阅读与修订操作区，`features/studies/*.css` 拥有专题页面及个人画布。字体许可见 [assets/README](src/assets/README.md)。

## 交互约定

- 上传成功后进入已有处理任务，不重复导入；切换页面保留正在上传的文件。
- 核对逐项对照原图，底部稳定操作区按步骤显示保留、修改、保存或提交，页清单可收起。中间疑点处理后进入下一处，最后一处进入本页检查；全部判断保存后仍须明确提交本页，草稿保存不表示内容通过。
- 当前疑点编辑为主要操作，整页编辑为次级操作；没有可靠位置时明确显示整页核对。
- 目录预览不提交决定。用户核对正文起点后确认跳转，也可保留目录文字而不设置跳转；物理页序与印刷页码分别显示。
- 提交失败保留输入，版本变化提示重新载入；成功回执与后台同步状态分开显示。
- 书籍 SSE 先读取快照与游标再接续事件；健康连接不额外轮询，断线只刷新可见的活动查询。原文索引完成但自动制卡任务尚未出现时短暂轮询就绪状态；独立任务仅在排队或运行中轮询轻量进度，停止、待人工或完成后停止轮询，卡片清单按新增结果或决定刷新。
- 未发布资料可查看底稿。修订待核验时继续读取已有发布版本，不能把候选当作已批准正文。
- 原文已入库与卡片进度分开显示。新史料卡自动经历制作、独立审核、按需修正与复核、待人工及完成；机器处理进度不表示人工批准，暂停和技术故障保留正常恢复操作。
- 本书检索保留原文范围与版本依据；实体库按名称、别名和类型筛选已核验记载，同名不自动合并。个人专题可整理自己的问题与论据，退役的自动研究问题和自动论文论证执行器继续停用。
- 全书阅读区分“阅读文本”和“对照原书”；检索本书与相关史料按需切换，模式及辅助栏切换保留阅读位置。史料卡的当前章节与展开引文写入绑定卡片版本的链接，返回时恢复对应位置。史料卡与原图可并排核对，支持选择引用、物理页和缩放；引用共用阅读器的版本哈希与精确位置，旧依据不能高亮新正文，返回链接保留检索和卡片上下文。正文中的实体链接仅用于当前版本中已验证的精确位置，相关卡片可在阅读侧栏查看。
- 完整卡片可修订编目、日期、内容要点、引文与事实、原文观点、疑义、实体、事件及证据关系；新流程不生成论文用途、研究计划或问题结论。修订草稿按工作区、卡片和原始基准版本保存在本机，折叠章节或返回阅读保留输入；版本冲突先核对最新卡片，再显式沿用草稿重新提交，读取最新版本不覆盖输入。修订创建新版本并重新独立核验，原有卡片和人工决定继续保留。未知元数据注明原因，新增实体须明确选择本卡原文中的称呼位置。
- 实体身份提供同一、不同、拆分、别名及撤回别名的显式决定，引用双方当前来源版本。事件分别标记材料报告、计划、条件和否定，材料报告不表示已得到独立互证。材料关系可核对双方冻结卡片及各自原文依据，不将对方卡片的局部引用编号当成本卡引用。
- 正文目录与卡片待办共用待办入口。原文核验通过与人工确认分别标记；待人工卡由用户采用、修订或排除，无需审核人姓名或意见。提交成功后进入下一项，冲突及读取失败保留草稿和成功回执。
- 人工备注独立保存并检查备注版本，不改变卡片核验状态，也不启动模型任务。版本冲突保留输入，读取最新备注并明确确认后方可再次保存。
- 旧研究任务、问题、选材、笔记和结论保留只读及 Markdown 导出；旧卡片中的论文用途与研究计划仍可查看，历史内容不会被就地删除或改写。
- 专题局部导航始终保留当前专题，切换恢复各视图的筛选与选中状态；没有有效专题时先明确选题，空专题不扩大为全库。继续工作按工作区保存明确访问的位置，由用户点击恢复。个人研究记录与手工连线不改变史料核验状态；选材固定卡片版本与证据，来源换版时明确提示。画布新建、重命名、复制布局、归档和备份恢复集中于“画布管理”，导出独立分组；自动保存检查版本，冲突保留草稿。JSON 恢复仅接受同工作区且可重新校验的本地来源，Markdown 保留引文和脚注。
- 时间线的日期依据、起止时间、来源材料与未定年条件统一提交后生效，明确显示尚未应用的修改及当前生效范围；当前条目的原文依据集中在侧栏，纪年查阅作为辅助工具。
- AI 分析按准备材料、制作与独立核验、查看建议与采纳三个步骤组织，结果逐条展示当前建议及对应依据。可直接采纳、修改个人解读后采纳、忽略或恢复建议；修改另存个人记录，机器原建议、冻结引用和核验结果继续保留。未获支持、已忽略或来源已变化的建议不可采纳。采纳创建独立个人记录，重复点击幂等；不自动写论文或批准原文。

## 检查与构建

```powershell
npm --prefix web run typecheck
npm --prefix web run check-unused
npm --prefix web test
npm --prefix web run build
```

`build` 先检查 TypeScript，再生成 `web/dist/`。测试默认最多使用 4 个 worker，避免与本地文档处理争用内存；不降低测试覆盖或延长超时。`npm --prefix web run preview` 在 18156 预览已有构建，仍依赖平台 API 和上传服务。

测试与功能代码同目录，组件测试与构建不代替真实史料验收；完整处理、原图核验、目录与脚注、检索及导出由项目端到端验收覆盖。
