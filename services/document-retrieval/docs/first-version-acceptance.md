# 史料索引与检索首版验收

2026-09-09。本模块已完成可运行实现与约定的机器验收。主测试集、新材料补测、工程恢复、Linux 最低路径及混合运行均有实际证据；已知失败和一次性能超时恢复继续保留。容量测试按用户要求暂停，用户最终接受为 pending。

## 交付与范围

版本 `0.1.0` 提供固定来源的文字／向量索引、精确与兼容查找、BGE 混合检索和重排、正文／相邻段／附注／整表后备／媒体回读，以及持久作业、增量接续、后台切代、任务保留、到期回收和配对备份恢复。HTTP、六个 Python Agent 工具与 CLI 共用合同。它为制卡提供取证工具，完整史料卡生成仍由后续模块完成。

安装及调用见 [模块说明](../README.md)，实际取证与恢复步骤见 [操作说明](operations.md)，重跑方法见 [复验入口](../evaluation/README.md)。[离线 OpenAPI](../contracts/openapi.json) 与同目录 JSON Schema 来自实际请求／响应模型。

本次按用户授权增加了入库模块的按证据范围机器复核入口，迁移头为 `0015_source_qualifications`。它保留原始正文、readiness 和活动限制，按明确用途披露机器资格；生成内容、未解决依赖及未复核范围仍受原约束。相关隔离 PostgreSQL 回归为 8/8，见 [入库扩展状态](../../document-ingestion/docs/implementation-status.md)。本次没有修改冻结提取模块的 OCR／表格算法或 DeepSeek 生产路由。

## 真实输入与评估口径

基础代表集为 21 个来源家族、60 项任务，按家族划分为 8 个校准家族与 13 个留出家族；任务为校准 20 项、原留出 40 项。另有未参与检索参数选择的两个来源家族和 12 项补测。总计 23 个来源家族、72 个合格固定任务；历史运行和性能重复请求不增加独立样本数。

[来源范围明细](../evaluation/final-acceptance-20260909-v1/corpus-summary.json) 记录 23 个登记 PDF 哈希、394 个 PDF 页面、387 个采用页面、115 个含合格文字的页面和 1,081 个合格来源范围。近代材料以节录载体及其原汇编页对应关系登记；“某页含合格文字”不表示整页文字均获准。

当前索引选定 26 个固定来源，公开状态均为 ready；文字记录 2,090/2,090、向量记录 1,046/1,046 已发布。[实际索引状态](../evaluation/development/final-index-status-20260909-v1.json) 保存请求、正文、响应头与哈希。四个已采用报刊快照没有合格正文，因此没有被计入正例索引。来源范围、派生记录、向量窗口与页数是不同单位。

采用范围为 48 页的长材料，当前获准文字仅有 22 段，位于物理页 14、24、25、44，完整阅读对照实取 2,657 个 Unicode 码点。前、中、后部任务据这些固定范围建立；没有将全部 48 页当作已准确提取或全部可检索。

三项原任务仍有冻结输入缺口：两处报刊标题缺失／误字，以及未知细字导致整页媒体无法放行。它们在首次检索前被替换，并保留原问题、原因及替换 ID，见 [输入预检](../evaluation/datasets/retrieval-representative-20260909-v7/preflight.json)。这些原任务不算成功。基础集合按所有已登记 ID 计为 63 项（60 项可测任务及 3 项缺口），当前完整取得 57 项；其中校准结果沿用配置锁定阶段的运行。加上新材料测试为 68/75，属于含缺口、含校准与已见回归的登记池统计，不能称作独立盲测成绩。

原件／页图先于资格和参考建立。运行中的 GPT 只按任务与实际公开响应决定下一次查询、展开或停止，不读取参考锚点替自己选命中。每题最多两次新检索、四次继续／展开、六次内容调用；相同固定来源集合共用保留及已收到的内容。所有实际 JSON 响应计入工具量，媒体字节另外记录。

同一 GPT 建立参考并审阅候选，因此以下全部是机器判定，非独立盲审、非用户人工史料审定、非 sealed gold。原留出在诊断后已成为已见回归集。附注重复与无关表格语境的更正保留旧版本，并对旧运行一致复评，见 [参考更正](../evaluation/datasets/retrieval-representative-20260909-v7/context-correction-review.json)。

## 模型与返回量

在校准集合比较 BGE 嵌入＋BGE 重排、关闭重排、单独替换 Qwen 重排和单独替换 Qwen 嵌入。BGE 基线取得 11/12 完整研究任务、34/37 必要组；关闭重排为 10/12、Qwen 重排为 9/12。Qwen 嵌入取得同样 34/37 组，但保留一次 I/O 失败，完整任务为 10/12。没有把该 I/O 失败归因于模型质量。

较长片段 512/1024/64 与较大预算 6/192/3000/6000 均未增加完整证据取得。按已确认的小差异保留基线原则，最终使用 BGE／BGE、384/768/64、首批 6 项／128 摘录／2,000 完整响应及 4,000 展开预算。[配置锁](../evaluation/development/final-configuration-lock-v1.json) 先于原留出运行；后续修复没有更换该模型、分块或预算配置。

计数器是固定 BGE tokenizer 的代理 token。两边返回的调用方会话标签相同；完整阅读的 1,323 个实际返回文字单位通过原始范围与哈希核对，27 个会话全部读完。[计量机器审阅](../evaluation/runs/gpt-holdout-regression-20260909-v2/gpt-tool-volume-review-v1.json) 与 [逐任务／会话差值](../evaluation/runs/gpt-holdout-regression-20260909-v2/tool-volume-comparison-v1.json) 保留全部增减项。

## 工程与 Linux

当前生产源码的必要单元检查为 **38 passed、0 skipped**，见 [JUnit](../evaluation/development/retrieval-unit-20260909-v12.xml)；Ruff 检查通过。工程协议以隔离来源、真实入库 HTTP、OpenSearch 和 SQLite 执行，18 份观察覆盖已确认的 11 个场景组。

这些观察包括两个实际终止／重启位置：引擎写入后、控制发布前，以及列表已发布、客户端尚未收到结果时。另实际完成停服 CLI 配对恢复，核验 428 个阶段文件与配对引擎快照，检查旧锚点／保留、水位、消费代次和缺件／错配包拒绝。原始失败、修复与重复观察均保存，见 [工程机器审阅](../evaluation/runs/engineering-protocol-20260908-v1/gpt-engineering-review-v1.json)。

工程运行后的四个源码文件变化限于有界结果等待、响应字段整理、相邻段／整表读取和用途观察摘要。当前 38 项检查、真实取证及 Linux 新运行覆盖相应变化，其余观察按哈希与影响分析承接，见 [工程承接说明](../evaluation/development/engineering-impact-20260909-v1.json)。这不表示全部 18 个故障在最后版本重新执行了一遍。

Linux 使用当前源码重建的不可变 Docker 镜像 `historical-document-retrieval:acceptance-20260909-v3`，显式 CPU FP32，在本 Windows 的 Docker／WSL2 后端运行。两个真实来源、六项精确／兼容／混合任务均通过；混合任务实际执行嵌入及重排。HTTP、Python 工具、原生 CLI 的中文路径、PNG／PDF 流式字节、HEAD／ETag／Range、真实容器重启后的旧列表和锚点回读均通过。

[Linux 机器审阅](../evaluation/runs/linux-minimum-20260909-v2/gpt-linux-review-v1.json) 保留当前源码及镜像依据；[真实 202→200 结果等待](../evaluation/runs/linux-minimum-20260909-v2/actual-result-wait.json) 另作补充。两个临时探针使用错误方法／路径的失败记录及更正也保留。Linux 证据只证明这条 CPU 功能路径，不代表 Linux GPU 性能或独立 Linux 主机容量。

## Windows 混合性能与容量

实测机器为 Intel Core Ultra 9 275HX（24 核／24 逻辑处理器）、系统报告 34,004,512,768 bytes 物理内存、RTX 5080 Laptop GPU（16,303 MiB），驱动 610.78，Windows 11 build 26200，见 [硬件记录](../evaluation/development/final-hardware-20260909-v1.json)。独立 Python 3.11.15、PyTorch 2.13.0+cu130、Transformers 4.57.6，Windows 推理为 CUDA FP16，BGE 嵌入 1,024 维。OpenSearch 3.8.0 与 Docker 镜像摘要固定；SQLite 实测 3.53.1、WAL、FULL 同步。

`final-mixed-20260909-v1` 用四个并发客户端完成 20 个固定请求的三轮热运行，共 60 个原搜索作业及其正文读取。**59 次客户端正常完成，1 次等待超过 900 秒后恢复**；全部作业最终完成。原失败、接续轨迹及 [性能汇总](../evaluation/runs/final-mixed-20260909-v1/performance-recovery-v2.json) 分别保存，没有事先约定延迟硬上限。
