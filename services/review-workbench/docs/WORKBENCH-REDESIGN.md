# 工作台整体重构与验证

日期：2026-09-11。用户确认后实施，桌面端；不改冻结的文档提取策略。

## 实际流程与职责

上传与 SHA-256 查重 → 分片续传 → 持久队列 → 项目转换/DeepSeek 审核 → 可用范围自动目录交接 → 入库正文 → 篇目候选 → 人工确认组织 → 后台检索分块与嵌入 → 符合条件时自动制卡 → 人工决定卡片采用。

正文的剩余风险与篇目组织是独立决定；允许已有可用部分继续，受限部分不能因其他操作而被放行。制卡 auto_sync 未开启时明确提示配置未开启，不伪称等待调度。

| 主要入口 | 职责 | 后续/异常路径 |
| --- | --- | --- |
| 材料中心 | 上传、管理处理队列、材料级回执 | 断网重选原文件续传；失败重试原任务；交接受阻单独恢复；正文风险跳到待办 |
| 待办审核 | 正文、篇目归属、卡片决定 | 误报单块直接放行；正文修订保存后核验；篇目按组预览应用；409 保留编辑，不自动覆盖 |
| 文献库 | 篇目、版本、出现位置、采用来源 | 尚无篇目时提示组织确认而非重复上传；固定来源保持只读 |
| 研究卡片 | 主/子 agent 进度与交付、卡片结果 | 暂停/继续/重试沿用版本核验；交付与接收分开；候选跳到集中审核 |

材料详情按明确回执链 conversion.handoff → import.receipt → partition.result 关联。检索新增 input_snapshot_id，与制卡 fixed_input 中的快照做精确关联；没有关联字段时不猜测。来源载体和其派生独立篇目有不同快照，不把前者的索引/制卡任务冒称为后者。全库独立任务保留在材料中心折叠诊断区。

## 保留、合并与清理

- 复用 Markdown/内嵌 HTML 表格编辑、正文草稿版本控制、逐问题导航、可拖动/键盘调宽三栏、原件对照。
- 篇目编辑增加直接修改名称、对照来源、整段移入另一篇目末尾。源字符范围与哈希不变；拒绝清空最后一个片段及自动改写补充/替代/缺失关系。复杂拆分合并留在高级草案，必须预览验证。
- 统一哈希详情路径，刷新可回到原任务；审核分类和视图选择记忆在 sessionStorage。后台上传组件保持挂载。
- 删除 LiveApp 中 Intake、Search；移除 ModuleWorkspace 的后台模块标签页壳。
- 删除 App.tsx、WorkflowApp.tsx、仅旧界面使用的 EvidenceView.tsx、api/client.ts。main.tsx 不再装载旧模拟 UI。
- 旧合同/模拟传输库及测试保留为历史兼容参考，不作为可访问页面。未删除业务数据或旧草稿。

## 只读后端变更

1. 入库 `/drafts?pending=true` 改为检查当前修订每个 operation 是否被 applied_draft_groups 的冻结预览覆盖；“所选组成功”不再等于整份草案完成。
2. 制卡 `/cards?pending=true|false` 支持候选待决定筛选，列表返回 pending_candidate_count 与可读 title。只计已 publication 的候选，扣除当前采用版本及对应候选的完整人工决定；部分决定和另一候选的决定不会清除它。
3. 检索 JobView 增加 input_snapshot_id，只投影已有任务输入；不暴露私密配置、不改调度。

三个服务需要重启加载新代码。本轮没有停止或重启生产进程，也没有执行生产模型。旧进程未返回新字段时，界面提示未提供/无法关联，不补造状态。当前未增加跨模块全量统一进度百分比。
