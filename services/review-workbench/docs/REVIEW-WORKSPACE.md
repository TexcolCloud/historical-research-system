# 正文审核修订与项目重核

2026-09-10，转换适配器 **1.8**。现已支持定向正文修订重核、单按钮人工误报放行、目录入库及同一载体新版本采用，也支持跨页面持续上传。**材料中心全流程聚合视图仍未完成，本轮不代表真实史料、分件和研究卡片的全流程验收。**

## 使用

1. 审核中心打开任务，在问题／Markdown 与 HTML 表格／原件三栏中核对。
2. 确认机器误报时，只需点击内容块中的“确认无误并放行”，不填表、不弹二次确认，不调用 OCR 或 DeepSeek。确有错误时才修改内容、填写说明、点击“保存到服务端”；保存仍是草稿，待审状态不变。
3. 顶部展开提交清单，点击“提交已保存修订并重核”。可一次提交多个已保存块；本机未保存修改不包含在内。
4. 后台期间保留上一版正文与待审数，显示重核状态及按首轮回执估算的进度。关闭页面不停止后端任务。
5. 重核后自动切换新正文；错误继续列入问题清单，合格部分自动交接。只有入库采用完成才显示“修订正文已入库并采用”。残留错误仍被拦截，不会整份放行。

跨页内容块可保存草稿，但需要明确逐页对应关系后才能正式提交；清单明确排除并提示，不猜测页码。VLM 占位坐标不当作精确错误矩形。缺失证据、不可读原件不强制通过。

### 审核台定位与编辑

- 三栏之间的两条分隔线可左右拖动，只改变相邻区域；宽度偏好保存在当前浏览器中，刷新或重新进入仍恢复。问题／正文／原件最小宽度分别为 180／280／250 px。双击分隔线或聚焦后按 Enter 恢复默认，左右方向键每次调整 10 px（Shift 为 40 px）；不会重建编辑器或清空草稿。
- 打开任务时定位首个问题所在物理页；点击问题或上／下一个问题，正文栏独立滚动到对应内容块，保留编辑入口。问题卡片按描述自动换行、增长高度，问题栏独立滚动。
- 问题编号同步显示在 Markdown 的待修订范围中，渲染与源码编辑状态均保留提示。定位依据是后端 `region.block_id`，属于内容块级，并非错误单字或单元格坐标；只有页级证据时明确提示无正文块定位，不猜测范围。
- 点击“编辑审核草稿”，再点击标题、正文或表格。正文工具支持正文段落、1—6 级标题、加粗、斜体、列表、引用及撤销／重做；HTML 表格沿用行列编辑。特殊语法和无法安全保留结构的表格仍可使用 Markdown 源码。
- 标题、正文、表格共同走现有草稿保存与项目重核流程；保存不等于放行。前端交互回归见 `output/playwright/hrs-workbench/review-editor-check.cjs`，开发评价见同目录 `review-editor-verdict.json`。

## 复用项目能力

- 适配器子进程使用文档转换虚拟环境，调用现有 semantic_completion.complete_document 和 artifacts.write_outputs。全页及相邻原件语境重核，不重新 OCR，不修改冻结模块代码、模型配置或生产规则。
- 生产仅调用配置的 DeepSeek。无配置、未完成或错误回执不能作为通过；GPT/Codex 只做开发 UI 检查，不参与生产改写或放行。
- attempts/N 新目录保存修订请求、原件页图、新 Markdown、重建偏移／来源映射／readiness／证据摘要。旧目录、草稿和原 PDF 保留。
- 入库已有 existing_carrier + reextract 产生同一载体的新内容和证据版本，默认 pending_adoption；再通过现有 draft → preview → application 的 set_reading 采用新载体正文，触发正常变更订阅。不是修改 ReviseDocument 元数据来冒充正文修订。
- 旧准备／导入回执即使只完成一半，也先恢复并确认载体身份，再处理新版本。准备、导入和采用回执持久复用，响应丢失不会重建操作身份。
- 旧快照及基于它的篇目、组织、研究卡片引用不直接改写，后续影响处理仍归各模块。

## API 与状态

转换服务 /api/v1/jobs/{job_id} 下：

- GET/PUT review-drafts/{block_id}：原草稿合同。PUT 绑定 attempt、markdown_sha256、expected_version、text、reason，要求 UUID Idempotency-Key，CAS 冲突 409；记录完整前后正文。保存回执 production_release=false。
- GET review-revisions：当前轮次最新服务端草稿摘要、当前及历史固定修订请求。
- POST review-revisions：UUID Idempotency-Key；JSON {attempt, markdown_sha256, drafts:[{block_id, version}]}。只接受各块最新已保存版；拒绝重复块、跨页绑定、旧轮次／旧摘要。202 仅表示排队。
- 修订状态 queued → running → verified / needs_review / failed。同任务仅一份活动修订，共用串行转换线程，不增加 GPU 并发。
- verified 不等于入库成功。交接独立经历 queued/running/waiting/blocked，新版本导入和采用完成才到 published。可用范围仍由块级 readiness 和入库限制决定；人工放行通过下述后端证据流程，不是仅隐藏前端问题。
- 中断后运行中修订转 failed，原正文保持有效；重提分配新目录，不覆盖失败轮次。等待服务／worker 时复用回执自动重试，非重试错误需检查后继续交接。
- 草稿在 state/workbench-conversion/tasks.sqlite3 的 review_draft_revisions 表；固定修订与历史在 jobs JSON。后续清理应同时覆盖数据库、上传目录和入库交付目录。

## 人工误报放行（1.7）

- `POST /api/v1/jobs/{job_id}/human-releases`，UUID `Idempotency-Key`；单按钮 JSON：`{attempt, markdown_sha256, block_id, confirmed:true}`。后端默认记录“本机人工审核 / 人工点击确认无误并放行”，不冒充已认证身份；兼容旧调用的 reviewer/reason。拒绝旧版本、非待审块、重复操作键的不同请求、当前块已有修改草稿及正在重核／交接的任务。
- `GET review-drafts/{block_id}` 的 `capabilities.human_release` 表示支持直接人工确认；旧 `release:false` 仍表示保存草稿本身不能放行。健康检查新增 `human_releases:block-v1`。
- 人工提交复用后台审核队列，`review_revision.kind=human-release`，202 只代表已接收。生成新 `attempts/N`，Markdown、来源映射、机器回执完全保留，不修改冻结转换模块；只将选定块设为可用，保留其他块与依赖限制。
- `human-release.json` 保存原始块判定、审核人／说明／时间、原件 PDF 摘要、页图摘要、正文及块摘要。`human-base-*.json` 保存原始证据用于校验仅批准的块发生可用性变更。机器原判不会被改成机器通过；人审标记为 `human_release:true, machine_review:false`。
- 问题清单只移除已批准块；其他错误及无块定位的页级问题继续待审。跨页块可以在核对全部相关原页后确认无误，但不猜测或放行无块定位的页级问题。
- 新版本自动目录交接并采用到同一载体，旧快照不改写。研究输入继续检查未通过的依赖。放行记录与正文修订重核记录分开展示。
- 正文不变时携带其他服务端草稿和同浏览器的本机草稿；失败保留旧正文与失败产物，可重新提交。其他块后续重核时，未修改块的人工结论保留并注明原版本；被修改的块不复用原人工结论。

### 定向复审与旧问题保护（1.8）

- 根因：旧适配器用整页／整份的新模型结果重新生成问题清单，导致未提交的旧问题只要未被再次提及就自动消失。
- `review_scope.py` 仅允许本次冻结提交的内容块采用新的复审结论。其余块保留原状态、问题、人工记录及依赖；问题卡片依据新正文偏移迁移，不靠变化后的块编号猜测。
- 批量提交仍逐一界定范围。标题／段落分裂导致编号变化时重新映射；未提交块无法精确映射、依赖失去定位或机器改动越界时，本轮失败，旧正文与待审状态保留。
- `review-scope.json` 记录提交块、保留块、新旧摘要与定位；它是范围合并记录，不是人工批准。机器原始回执保留。健康检查提供 `review_scope:submitted-blocks-only-v1`。

- 第 4 轮 `review_revision.kind=scope-recovery`，不是新的人工放行或模型复审。交接使用经入库 API 确认的原载体，不恢复错误的第 3 轮未完成交付；研究输入采用沿用现有入库 API，待审限制随新来源证据传递。
