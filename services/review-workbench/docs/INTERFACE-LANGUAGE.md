# 工作台命名与操作提示核查

核查日期：2026-09-11。范围为实际挂载的 `src/live` 工作台：材料中心、正文审核、篇目划分、文献库、任务监控和卡片审核。未启用的演示状态模型、历史验收记录不作为当前界面用词来源。

## 扫描结果与处理

| 问题 | 原表现 | 本次统一方式 |
| --- | --- | --- |
| 同一操作多种名称 | 分件、篇目组织、组织安排 | 日常界面统一为“篇目划分”；待确认内容为“篇目划分方案” |
| 关联修改被误称为文章分组 | 依赖组、篇目组、应用所选组 | “需一起确认的修改”；列出篇名和具体操作，保留后台原子生效约束 |
| 修改序号均为零 | 对重新解析后的对象使用 indexOf | 使用当前列表索引，浏览器验证“修改 1、修改 2”及稳定后台 ID |
| 保存与生效混淆 | 保存草案修订、应用结果 | “保存修改（尚未生效）→ 预览确认结果 → 确认并生效 → 刷新确认结果” |
| 人工与机器审核混称 | 重核、复核、人审、待补证 | 机器操作称“机器核验”，人工操作称“审核/放行”；正文保存草稿不放行 |
| 卡片交付与采用混淆 | 不可变修订、固定预览、产物 | “候选与历史版本”“审核预览”“交付记录”；明确候选不等于已采用 |
| 后台名词直接外露 | worker、快照 UUID、字符偏移、英文阶段 | 常用状态集中映射；编号、来源定位记录和 JSON 放入诊断，未知阶段不猜测成功 |
| 页码与版本含义不清 | 物理页、篇目版本 | 原件按文件页面顺序编号，区别印刷页码；文献版本标注刊本、译本等，避免混同正文修改 |
| 上传提示夸大持久性 | 所有上传进度均保存于服务端 | 区分已接收进度与仍在本机的待上传文件 |
| 重复或过时指引 | 处理任务、审核中心、手动目录交接 | 使用当前导航“材料中心”“待办审核”；恢复操作统一为“重试入库” |

## 后续用词规则

- 保存：编辑内容已保存，不表示已生效、放行或采用。
- 放行：人工确认特定正文范围无误，不运行机器复审，不解除其他问题。
- 生效：本次所选篇目修改已按后台结果实际完成；仅提交请求不能显示成功。
- 采用：卡片审核选择当前使用的内容。交付已保存、机器核验通过均不自动等于人工采用。
- 完成：明确是哪项任务或阶段完成，不能代替全流程完成。
- 源材料、独立篇目、文献版本、正文修订、研究输入之间的区别继续保留，不用简单更名抹平。
- 后台接口键、状态值、来源证据、机器原始问题说明不做字符串改写。必要技术信息保留在诊断中；不能识别的新状态保守提示，并保留原记录。
- 简单操作使用已有可视化控件；复杂拆分、合并、补配等仍明确标注为高级编辑，不假称已提供完整可视化能力。

领域术语已同步到根目录 `CONTEXT.md`。本次不修改生产管线、OCR、审核资格、自动同步配置、数据库或接口合同。
