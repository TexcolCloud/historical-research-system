## 行为与接口

- 选择或拖入多个 PDF 即开始顺序上传；每文件独立回执和重试，单文件 256 MiB 上限。上传完成后按顺序进入服务器处理队列；转换仍使用项目 PaddleOCR-VL / DeepSeek 管线。
- `POST /api/v1/jobs?filename=...&enqueue=true` 在验证和落盘后原子排队。省略 enqueue 保留旧客户端仅上传能力。队列每 2.5 秒刷新，已完成历史分开显示并刷新。
- `GET /jobs?queue_only=true` 读取先进先出队列，`completed_only=true` 读取历史，均保留分页。服务重启保留尚未开始的 queued 项；原 running 项仍需显式重试。
- `DELETE /jobs/{id}`：上传 / 排队 / 失败 / 中断项取消并删除文件；运行项先返回 202 cancelling，退出后才删除。完成项返回 409，避免破坏已交接来源。旧 controls 的 cancel 也使用删除语义。
- 删除成功后文件、任务目录和队列项均移除；数据库仅保留取消 ID，阻止迟到的请求重新创建任务。同 ID 重传返回 410，重新选择文件生成新 ID。已取消的文件不能直接重试，需重新上传。
- 尚未传完的浏览器 File 对象不能跨刷新恢复，因此上传期间提示勿关闭或刷新。取消最多等待约 30 秒确认，超时保留重试入口，不谎报删除完成；已发生的模型调用费用不能撤销。

## 选择器排查与验证

改动前内置浏览器能捕获 filechooser 事件，因此没有证据将用户所见的系统弹窗不可见归因于某个前端错误。新按钮显式调用原生 showPicker（不支持时使用 click），浏览器测试确认触发多选事件；捕获事件不等于证明用户侧系统弹窗可见。

- 前端 30 项、转换适配器 21 项通过；构建通过，保留既有大块体积警告。取消后文件暂被占用的场景保留重试状态，不终止转换 worker。
- 浏览器隔离夹具验证独立选择按钮、多选、直接入队、取消移除、拖拽上传、刷新恢复共 6 项，无页面错误。
- 后端验证原件 / 目录删除、取消 ID 防复活、上传中取消、运行中停止后删除、重启保留排队。实际入库目录交接隔离回归 3 项通过。
- 浏览器只请求夹具，Python 测试使用临时目录和模拟 runner；未转换用户 PDF，未调用真实模型。
