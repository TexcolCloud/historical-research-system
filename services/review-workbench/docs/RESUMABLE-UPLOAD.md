# PDF 断点续传与内容去重

2026-09-10，转换适配器 1.4。复用现有 SQLite、UUID 任务目录和单进程 FIFO worker；未引入新依赖，未修改文档识别或 DeepSeek 复核。

## 用户行为

- 多选或拖入文件后，浏览器逐文件计算 SHA-256，查询已有任务，再以最多 4 MiB 分块顺序上传。上传百分比按服务器确认的字节数计算，与处理阶段的估算百分比分开。
- 文件内容相同（SHA-256 与长度相同），即使文件改名，也复用原上传会话或原任务；排队、运行、失败、中断、完成任务都参与去重。失败任务由用户在原任务显式重试，不因重复上传再次启动。
- 网络中断保留已确认分块。单次响应丢失会先查询服务端偏移后补传，连续失败停止并显示重试入口。页面刷新、浏览器关闭后，本地 File 无法保留；队列显示“选择原文件继续上传”。重选后重新核对内容，继续已有上传。
- 完整接收后，服务端重新计算整个文件的 SHA-256、检查长度和 PDF 签名，成功才自动排队。校验失败只删除该会话的错误字节，保留上传记录，允许重试；绝不把未验证文件交给转换管线。
- 取消未完成上传会删除 source.part、原件及任务目录，同时移除队列记录；取消 ID 保留为防迟到请求记录。相同内容之后可以以新 ID 从头上传。运行任务依然先停止再删除；已完成交接的任务不能从上传队列删除。

## HTTP 合同

以下路径相对 `/api/v1`，浏览器通过同源 `/modules/conversion` 代理访问。

| 方法 / 路径 | 输入与结果 |
| --- | --- |
| POST `/uploads` | JSON `{filename, byte_length, sha256}`，可选 UUID `Idempotency-Key`（前端始终提供）；返回规范 `job_id`、state、upload_offset、chunk_size。客户端必须采用返回 ID。非 uploading 状态为已有任务，duplicate=true，不再传字节或排队。 |
| GET `/uploads/{id}` | 返回服务端实际文件长度作为 upload_offset；不是客户端猜测进度。 |
| PUT `/uploads/{id}?offset=N` | 原始字节，非空、最多 4 MiB。先完整接收一块，再在锁内校验偏移、追加并 fsync。偏移不符 409，取消后 410，过大 413，超出声明长度 422。成功返回新偏移。 |
| POST `/uploads/{id}/complete` | 缺字节 409；内容校验失败 422 并重置偏移；成功原子重命名 source.pdf、发布 queued 状态。重复提交返回原任务，不重新排队。重启可恢复重命名与发布状态之间的中断。 |
| GET `/jobs?queue_only=true` | 上传中记录也显示，含 upload_offset、byte_length。处理 worker 只消费 queued。 |
| DELETE `/jobs/{id}` | 延续“取消并删除”合同，同时覆盖未完成上传。创建会话前取消也记录 tombstone，拒绝迟到创建。 |

旧 `POST /jobs?filename=...&enqueue=true` 保留，但落盘前也按内容复用现有任务，不能绕过去重。旧入口仍需整文件传输；它不是续传接口。

## 保存与约束

- SQLite 记录会话声明；UUID 目录的 source.part 保存已接收字节，source.pdf 是最终通过校验原件。分块请求中断不写入不完整请求体；进程崩溃后以实际文件长度恢复，最终完整摘要兜底。
- 同一 state-root 只允许一个适配服务进程。当前 RLock 串行化内容查重、创建、写入、发布和取消；多人多进程部署时需升级为数据库唯一内容占用与任务租约，本次不引入。
- 内容去重是字节级，不是语义相似度检测。重新扫描、重压缩或改写 PDF 元数据造成字节变化时视为不同文件。
- 单文件 256 MiB。浏览器原生 Web Crypto 一次读取一个文件计算摘要，内存开销可接近文件大小；不会同时计算整批文件。未增加自动过期删除，未完成会话保留到人工取消。
- 1.6 上传控制常驻应用外壳，切到其他页面仍继续传输，显示全局状态与管理入口。整个浏览器刷新后仍需重选原文件恢复；不是 tus 标准实现。
